# Contributing

Anyone can read, install and fork this repo. Changes reach `main` only through a pull request. The full rules are
in [`docs/contributing/`](./docs/contributing/README.md); this page is the short version. Back to [AGENTS.md](./AGENTS.md).

## Route

1. Fork the repo (or, with write access, push a branch here).
2. Open a pull request against `main` and fill in the template.
3. CI must pass: `bridge`, `server`, `plugin` and `docs` are required checks.
4. The code owner reviews. A new push dismisses an earlier approval.
5. The owner merges with a **merge commit**; squash and rebase merges are disabled so branch history is kept.

Direct pushes, force-pushes and deleting `main` are blocked for everyone. Release tags (`v*`) are created by the
owner only. CI runs for first-time and outside contributors wait for the owner's approval.

## Local checks

```bash
cd plugins/whatsapp/bridge && gofmt -l . && go vet ./... && go test ./...
cd plugins/whatsapp/server && uv run --with pytest python -m pytest tests -q
plugins/whatsapp/hooks/test-bypass-guard.sh
python3 scripts/check-docs.py
```

## Ground rules

- Changes to the guard files listed in `.github/CODEOWNERS` need a sentence in the PR on why bypass mode still
  can't reach the WhatsApp tools.
- Never commit real phone numbers, chat names, message content, `~/.whatsapp-mcp` files or tokens. Test data is
  generated by `bridge/fixture_test.go`.
- Doc first: the ADR or doc commit comes before the code ([documentation mandate](./docs/contributing/documentation-mandate.md)).
- Security issues: see [SECURITY.md](SECURITY.md), not a public issue.
